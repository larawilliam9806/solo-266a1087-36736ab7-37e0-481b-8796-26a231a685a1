# 地铁每日首程客流 · 差分隐私查询平台

地铁数据分析员向合作研究方提供每日首程客流统计的网页服务。基于 **Flask + SQLite**,
对每次新查询的结果添加 **Laplace(0, 2)** 噪声(安全随机源 `secrets.SystemRandom`),
并按 **每次 0.5、每日总额 2** 的隐私预算计费。查询页只显示加噪结果。

首程 CSV 开放查询后若发现漏记,锁定的源数据不可直接替换,可通过 **整日订正**
生成新修订:上传完整新 CSV 并携带所见修订号,成功后当前修订 +1,
旧原始行不再参与新查询,已发布的带噪结果留在原修订供原值回查。

## 快速启动

### Docker Compose(推荐)

```bash
docker compose up --build
```

访问 http://localhost:8000 。SQLite 数据库保存在名为 `appdata` 的卷中,
容器重启后已发布结果、预算消耗、锁定状态与当前修订号均不丢失。

### 本地运行

```bash
pip install -r requirements.txt
python app.py            # 开发模式, 监听 8000 端口
# 或: gunicorn --bind 0.0.0.0:8000 --workers 2 --threads 8 app:app
```

数据库路径由环境变量 `APP_DB` 指定(默认 `./app.db`, 容器内为 `/data/app.db`)。
旧版(无修订号)数据库在启动时自动迁移,存量源数据与已发布结果全部归第 1 版。

## 功能与规则

| 规则 | 实现 |
| --- | --- |
| 按日期上传 CSV(乘客ID, 进站, 出站), 每位乘客仅一行 | `POST /upload`, 乘客ID 重复即拒绝; 支持中/英文表头或无表头 |
| 锁定前可整日替换, 首个成功查询后拒绝替换 | `day_state.locked`, 替换与锁定检查在同一事务内 |
| 整日订正: 完整新 CSV + 所见修订号, 成功后当前修订 +1 | `POST /correct`, 沿用乘客ID 与列校验 |
| 同版并发订正只接受一次 | `BEGIN IMMEDIATE` 串行化 + 事务内比对 `current_revision`, 不一致即 409 |
| 订正后旧原始行不参与新查询, 已发布结果留在原版 | 源数据与结果均按 `(date, revision)` 隔离, 计数只读当前修订 |
| 存量数据与结果归第 1 版 | 启动时自动迁移旧库, `revision` 一律置 1 |
| 查询携带修订号: 旧版已发布条件原值重查, 未发布过的拒绝 | `POST /query` 的 `revision` 字段; 旧版仅命中缓存才返回, 否则 409 |
| 当前版同条件重新加噪并扣当日剩余预算, 跨修订不退还 | 结果主键 `(date, revision, in_key, out_key)`; 预算按日累计于 `day_state.budget_spent` |
| 选择进/出站集合查询匹配人数 | 集合与顺序、重复选择无关(排序去重后规范化) |
| 新查询加 Laplace(0, 2) 噪声, 扣 0.5 预算, 每日总额 2 | 逆变换采样 + `day_state.budget_spent` |
| 相同修订下相同查询复用原结果, 不再扣费 | `queries` 表主键命中即返回 |
| 并发不超支、相同查询只生成一份结果 | `BEGIN IMMEDIATE` 写事务串行化 + 事务内复查 + 主键约束 |
| 预算不足不返回新结果 | 事务内检查, 不足即回滚并返回 403 |
| 订正与查询交错时成功查询只归属完整一版 | 查询的读修订号、计数、扣费、写结果在**同一写事务**中, 与订正严格串行 |
| 校验/保存失败、重启后不出现修订号、源数据与结果错配 | CSV 校验先于写库; 新修订行写入与修订号切换同事务; 状态全部持久化于 SQLite |

## API

### `POST /upload`
表单字段: `date`(YYYY-MM-DD), `file`(CSV 文件) 或 `csv`(CSV 文本)。
- `200` `{ok, rows, revision}` 替换当前修订成功
- `400` CSV 非法(空字段、乘客ID 重复、列数不足等)
- `409` 当天源数据已被首个查询锁定, 请改用整日订正

### `POST /correct`
表单字段: `date`, `revision`(所见修订号), `file` 或 `csv`。
- `200` `{ok, revision, rows}` 生成新修订, 当前源数据切换
- `400` 修订号缺失/非法, 或 CSV 校验失败(不产生新修订)
- `409` 当天尚无源数据, 或所见修订号已过期(含同版并发订正)

### `POST /query`
JSON: `{"date": "2026-11-01", "in_stations": ["西直门"], "out_stations": ["国贸", "望京"], "revision": 2}`
- `revision` 可省略, 缺省为当前修订
- `200` `{ok, noisy_count, cached, revision, current_revision, budget_remaining}` — 只返回加噪人数
- `400` 修订号不是正整数
- `403` 当日预算不足, 不返回新结果
- `409` 修订号不存在, 或旧修订未发布过该条件(历史修订仅支持已发布结果的原值重查)
- 相同 日期 + 修订 + 站点集合(任意顺序/重复)返回首次发布的同一数值

### 其他
- `GET /api/stations?date=` 当前修订出现过的全部站点(供页面多选)
- `GET /api/status?date=` 当前修订号、行数、锁定状态、预算消耗
- `GET /api/queries?date=` 当天已发布的全部加噪结果(按修订分组, 页面分版展示)

覆盖: 上传替换与锁定、规范化复用(乱序/重复)、预算上限(4 次新查询)、

Laplace(0, 2) 噪声分布(均值 0、方差 8)、
整日订正(新修订切换、同版并发仅一次、校验失败不留痕)、
分版查询(旧版原值重查/未发布拒绝、当前版重新加噪扣费、预算跨修订不退还)、
订正与查询交错时的单版归属、订正后重启一致性、旧库自动迁移(存量归第 1 版)。
